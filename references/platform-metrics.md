# 平台指标口径与采集窗口

## 为什么需要这张表

同一个数字，小红书后台叫「观看量」、抖音叫「播放量」、公众号叫「阅读量」、B站叫「播放量」、TikTok 叫「Views」，而在飞书表里可能被写成 `views` / `播放` / `vv` / `PV` / `impressions`。

**口径不统一的直接后果**：预测写 `播放`、回填写 `views`，两边对不上——系统静默不统计，命中率分母悄悄少一条，你还以为标准在进步。本台账用一张别名表强制归一：**认不出的名字直接报错，不许静默跳过**。

## 规范指标键

| 规范键 | 通用名 | 单位 | 说明 |
|---|---|---|---|
| `views` | 流量 | 次 | 曝光的可衡量代理指标，各平台叫法不同 |
| `likes` | 点赞 | 个 | 公众号=在看 |
| `comments` | 评论 | 条 | 含回复 |
| `collects` | 收藏 | 个 | B站可选；公众号=B站以外无 |
| `shares` | 分享 | 次 | 视频号=转发；B站=投币/转发 |
| `fan_delta` | 涨粉 | 人 | **增量**，不是粉丝总数 |
| `dm` | 私信 | 条 | 咨询数，教育类核心转化前置指标 |
| `conv` | 转化 | 单 | 下单/留资/试听预约 |
| `gmv` | 成交额 | 元 | 电商/带货口径 |

## 平台指标集（`init --platform` 决定）

| 平台 key | 显示名 | 默认指标顺序（第一个 = 主指标） | 默认采集窗口 |
|---|---|---|---|
| `xhs` | 小红书 | 观看量 → 点赞 → 收藏 → 评论 → 分享 → 涨粉 → 私信 | 24h / 7d / 30d |
| `douyin` | 抖音 | 播放量 → 点赞 → 评论 → 分享 → 收藏 → 涨粉 → 转化 | 2h / 24h / 7d |
| `shipinhao` | 视频号 | 播放量 → 点赞 → 评论 → 转发 → 收藏 → 涨粉 | 24h / 7d |
| `bilibili` | B站 | 播放量 → 点赞 → 评论 → 收藏 → 投币/转发 → 涨粉 | 48h / 7d / 30d |
| `tiktok` | TikTok | 播放量 → 点赞 → 评论 → 分享 → 涨粉 → GMV | 24h / 72h / 7d |
| `gzh` | 公众号 | 阅读量 → 在看 → 评论 → 转发 → 涨粉 | 24h / 7d |
| `custom` | 自定义 | （自定义） | 24h / 7d |

> 主指标 = 该平台**最先被推荐机制放大的那个数**。校准（`calibrate`）默认用主指标算秩相关。教育类账号如果私信/试听预约才是真目标，可以在 `init --platform xhs,douyin` 后手动把 `dm` 或 `conv` 视作业务主指标，但**评分卡校准仍建议用 `views`**——内容质量和流量质量是两件事，混在一起测不准。

## 采集窗口的用途

| 窗口 | 用途 |
|---|---|
| 抖音 2h | 判断是否进推荐池（早期断崖 = 内容问题，中途断崖 = 完播问题） |
| 24h | 主校准窗口，绝大多数平台流量已出 70-90% |
| 72h / 7d | 长尾与搜索流量（小红书/公众号/B站长尾占比高） |
| 30d | 号内爆款的持续价值，用于判断选题复用 |

**规矩**：`collect` 时用 `--window 24h` 标记，别把 24h 数当 7d 数比。同一账号不同窗口的命中率分开看。

## 数字写法

`--metric` 后的值支持：

| 写法 | 解析 |
|---|---|
| `10000` | 10000 |
| `1万` / `1w` | 10000 |
| `1.52万` | 15200 |
| `4.2w` | 42000 |
| `10k` / `1千` | 10000 / 1000 |
| `1,000` | 1000 |
| `1万-2万` | 区间 [10000, 20000] |
| `20000-10000` | 自动纠正为 [10000, 20000] |
| `5000` | 退化为点区间 [5000, 5000]（不推荐，点预测在内容行业是假装精确） |
