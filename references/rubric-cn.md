# 七维评分卡（中文内容平台口径）

发布门槛：**总分 ≥3.5** 才发；<3.5 回炉或直接放弃。总分 = Σ(维度分 × 权重)，维度分 1-5。

## 权重表

| 维度 | key | 权重 | 一句话判据 |
|---|---|---|---|
| Hook 强度 | `hook` | 25% | 前 3 秒有没有给出"必须看下去"的理由 |
| 完播结构 | `retention` | 20% | 节奏有没有钩子链，时长和密度匹配吗 |
| 价值密度 | `value` | 15% | 这条的价值能不能一句话复述 |
| 场景匹配 | `scene` | 15% | 是不是目标人群的高频真实场景 |
| 互动钩子 | `engage` | 10% | 有没有明确的评论/收藏/转发诱因 |
| 转化路径 | `convert` | 10% | 内容本身是不是使用场景，引导顺不顺滑 |
| 平台感 | `native` | 5% | 符合该平台的内容语法与本地梗吗 |

> 判断"这条能不能火"，Hook 和完播就占了 45%。**给不出 4 分以上的 Hook，其他维度再高也救不回来**——这是评分卡里最该严格执行的一条。

## 维度分锚点

打分不许停留在"感觉还行"。每维按下面锚点定档：

### Hook 强度（25%）

| 分 | 锚点 |
|---|---|
| 5 | 前 3 秒同时给出**具体冲突 + 悬念**，且不需要背景知识就能看懂（例：「我花了 800 块，让孩子拆了一台新手机」） |
| 4 | 前 3 秒给出明确悬念或反常识结论，但需要一点背景 |
| 3 | 前 3 秒是话题陈述，没有钩子也没有信息缺口（「今天讲讲传感器」） |
| 2 | 前 3 秒是自我介绍/品牌露出/寒暄 |
| 1 | 前 3 秒无信息（空镜、片头动画、无字幕慢动作） |

### 完播结构（20%）

| 分 | 锚点 |
|---|---|
| 5 | 每 5-8 秒一个信息增量或转折，钩子链完整，结尾有闭环 |
| 4 | 有明确节奏设计，中段有 1 处拖沓 |
| 3 | 线性叙述，靠内容本身撑，无节奏设计 |
| 2 | 中段有连续 >10 秒无增量内容 |
| 1 | 全程平铺直叙，明显可预判结尾 |

### 价值密度（15%）

| 分 | 锚点 |
|---|---|
| 5 | 单点价值清晰到能一句话复述，且复述出来别人会想收藏 |
| 4 | 有一个明确可复述的价值点 |
| 3 | 价值点存在但被淹没在信息里 |
| 2 | 有信息无价值（说了很多，没结论） |
| 1 | 无信息增量（复述不出来） |

### 场景匹配（15%）

| 分 | 锚点 |
|---|---|
| 5 | 命中目标人群**最高频**场景，且该场景有明确痛点 |
| 4 | 命中真实场景，但不算高频 |
| 3 | 场景相关但泛（「家长都关心孩子成长」） |
| 2 | 场景是需要被论证才成立的 |
| 1 | 无场景（纯自嗨/纯品牌视角） |

### 互动钩子（10%）

| 分 | 锚点 |
|---|---|
| 5 | 有天然的站队/选择/求助式提问，评论区能自己吵起来 |
| 4 | 有明确提问或收藏理由 |
| 3 | 有软性引导（「你觉得呢」） |
| 2 | 无引导，靠内容自发 |
| 1 | 结尾是硬广 |

### 转化路径（10%）

| 分 | 锚点 |
|---|---|
| 5 | 内容本身就是使用场景的演示，转化是顺带发生的 |
| 4 | 有自然的需求承接点（评论区/主页/私信任一） |
| 3 | 有引导但突兀 |
| 2 | 转化点与内容无关 |
| 1 | 无转化设计 |

### 平台感（5%）

| 分 | 锚点 |
|---|---|
| 5 | 完完全全长在这个平台上（选题、语感、封面、字幕节奏） |
| 4 | 基本适配，个别元素出戏 |
| 3 | 换个平台发也看不出来 |
| 2 | 明显是别平台的内容搬运 |
| 1 | 平台禁区（如小红书发硬广式详情页） |

## 平台微调

| 平台 | 权重调整建议 |
|---|---|
| 小红书 | `scene` ↑（搜索长尾强，场景词决定流量）、`native` ↑（封面+标题权重高于抖音） |
| 抖音 | `hook` ↑ 到 30%、`retention` ↑（推荐制对完播极敏感） |
| 视频号 | `engage` ↑（社交推荐靠转发） |
| B站 | `value` ↑（用户容忍长内容，但要求信息增量） |
| TikTok | `native` ↑ 到 10%（本地化是硬门槛） |
| 公众号 | `value` ↑、`hook` ↓（打开后的阅读意愿由标题决定，标题单独评） |

改权重也要走下面的升级流程，别随手调。

## 升级流程（改评分卡的唯一合法路径）

1. **攒证据**：同一观察被 ≥3 条独立复盘支撑（`review --obs-code` 自动累计，`observations.md` 里 ★ 标记）
2. **写变更**：在 `rubric.changelog` 里记 `{version, date, change, evidence: [证据编号], retest}`
3. **回测**：用近 10 条数据跑 `calibrate`，看 ρ 有没有变好
4. **版本号 +1**：v1 → v2，旧版本留档，别删

```bash
python3 scripts/content_ledger.py calibrate <账号>
```

## 校准读数怎么看

| 读数 | 含义 | 动作 |
|---|---|---|
| ρ ≥ 0.5 | 评分卡有效，高分确实更跑得动 | 继续攒样本 |
| ρ 0.3-0.5 | 方向对但区分度不够 | 调权重（不是加维度） |
| ρ < 0.3 | 现有关键维度不是主要矛盾 | **换维度**，别调权重 |
| 维度 ρ ≈ 0 且 ≥5 条 | 该维度失效 | 删除或重新定义（先确认不是评分口径问题） |
| 分档比值单调递增 | 评分档位设计合理 | — |
| 分档比值不单调 | 门槛位置错了 | 移动 gate，别改维度 |

## 反模式清单

- ❌ 单条爆款就改评分卡（样本=1，拟合噪声）
- ❌ 为了让命中率好看而事后收窄预测区间（指纹会抓）
- ❌ 维度加到 >10 个（每维样本被稀释，全测不准）
- ❌ 用"感觉这条会火"替代可验证依据（`--note` 里必须是：对标数据 / 上次同题表现 / 评论区高频问题）
- ❌ 把 `report` 当复盘（只看了数据 ≠ 想明白了偏差从哪来）
- ❌ 评分卡改了不回测（新标准可能比旧的更差）
